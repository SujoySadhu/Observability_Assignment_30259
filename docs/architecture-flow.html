ShopLite Observability Architecture

How traffic, metrics, logs and alerts move through the lab for candidate 30259. Everything runs in one Ubuntu VM at 192.168.56.20: the shop and the monitoring stack in Docker Compose, and a small order-worker in MicroK8s whose logs Alloy ships to Loki.

HTTP traffic Metrics (pulled by Prometheus) Logs (pushed to Loki) Grafana queries Alert email Arrows show which way the data travels. Numbers match the steps below.

1–2 · Traffic into the shop

  1. You open http://192.168.56.20:8080. nginx serves the static shop and logs each request as JSON.
  2. Calls under /api/* are proxied to api:8000 on the Compose network, with an X-Request-ID header.
  3. FastAPI handles orders, cart, login and coupons, and reads and writes Postgres. Postgres has no published port.
  4. The order-worker pod in MicroK8s calls the same API through the host-only IP every 5 seconds. Every 6th call asks for a product that does not exist, so you get a steady stream of 404 errors.

Deliberate flaws are on by default: slow queries, a memory leak, a coupon bug and slow login.

3 · Metrics

  1. Each request updates counters and histograms in the API process: http_requests_total, http_request_duration_seconds, http_requests_in_progress, orders_created_total, orders_failed_total and more.
  2. Every 15 seconds Prometheus pulls api:8000/metrics (job shoplite-api), 192.168.56.20:9100 (job node) and itself.
  3. Each scrape also records up: 1 when the target answered, 0 when it did not. The alert is built on this.
  4. Samples are kept for 7 days in the prometheus-data volume.

4 · Kubernetes logs

  1. The worker prints level=INFO … to stdout and level=ERROR … to stderr, unbuffered (python -u).
  2. The container runtime stores those streams. The kubelet serves them through the Kubernetes API.
  3. Alloy discovers every pod, turns Kubernetes metadata into the labels namespace, pod, container and app, and tails the logs.
  4. Alloy pushes them to http://192.168.56.20:3100/loki/api/v1/push with cluster="microk8s-obs-lab". Loki stores them in loki-data.

5–7 · Dashboards and alerts

  1. Grafana starts with the Prometheus and Loki data sources, the dashboard and the alert rule already loaded from grafana/provisioning.
  2. Dashboard panels run PromQL for CPU, RAM, disk, network, RPS, 5xx rate, p95 latency and orders, and LogQL for order-worker errors.
  3. Every 30 seconds Grafana checks up{job="shoplite-api"} < 1. Once it has been true for 1 minute, the alert fires. No data counts as down.
  4. The email-oncall contact point sends mail through Gmail on port 587 with STARTTLS. A RESOLVED email follows when the API is back.

Ports bind to the host-only IP rather than 127.0.0.1 so that MicroK8s pods can reach the API and Loki. Only Kubernetes pod logs reach Loki. The nginx JSON access log and API logs stay in docker compose logs. Secrets (database, Grafana admin, SMTP App Password) live only in .env.
